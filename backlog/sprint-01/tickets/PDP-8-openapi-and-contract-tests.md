# [PDP-8] OpenAPI 3.1 스펙 + 계약 테스트(Pact)

**타입**: Task ・ **SP**: 3 ・ **담당**: 김도현 ・ **요구자**: Priya Raghavan

## 배경
Storefront 팀(프론트)과 모바일 앱 팀이 이 API를 소비한다. 21개 마켓플레이스에 배포된 앱은 **롤백할 수 없다.** 하위 호환이 깨지면 앱스토어 심사 주기만큼 고통이 지속된다.
또한 Pricing 팀이 9월에 Kafka 스키마를 바꾼다고 예고했다. (PRD 리스크 R2)

## 해야 할 일
- OpenAPI 3.1 스펙 작성 (contract-first)
- 소비자 계약 테스트(Pact): Storefront, 모바일 앱
- 제공자 계약 테스트: Catalog Core / Pricing / Inventory / Delivery / Review 에 대한 우리의 기대
- CI에 계약 검증 단계 추가

## 인수 조건
- [ ] **AC1.** 스펙에 S1~S9 모든 응답 형태(200/404/410/503)와 예시가 포함된다.
- [ ] **AC2.** 스펙과 실제 구현의 불일치를 CI가 잡는다.
- [ ] **AC3.** 하위 호환을 깨는 변경(필드 삭제, 타입 변경, enum 값 제거)을 CI가 자동 감지해 실패시킨다.
- [ ] **AC4.** `availability` enum에 새 값이 추가될 때 소비자가 안전하게 무시할 수 있는 규약이 문서화됐다.
- [ ] **AC5.** 에러 응답 포맷이 사내 표준(RFC 9457 problem+json)을 따른다.
